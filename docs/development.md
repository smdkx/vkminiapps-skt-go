# Разработка

## Запуск и проверка

Нужен Node.js 22.13.0 или новее. Для nvm в [`.nvmrc`](../.nvmrc) выбрана ветка 22. Скрипты и точные версии зависимостей находятся в [`package.json`](../package.json).

```sh
nvm use
npm ci
npm start
```

Приложение будет доступно на `http://127.0.0.1:3000/`. Обычный браузер подходит для проверки верстки. Авторизация, VK Donut, нативный просмотр изображений и другие функции Bridge требуют запуска внутри VK.

```sh
npm run lint
npm run build
npm run preview
```

Сборка сохраняется в `build/`; `preview` запускает ее на том же порту 3000, поэтому сначала остановите сервер разработки. Настройки сборки находятся в [`vite.config.mjs`](../vite.config.mjs). Отдельного тестового скрипта сейчас нет. Lint и сборка не заменяют проверку переходов, ошибок загрузки и поведения в клиентах VK.

## Добавление экранов

1. Создайте панель в `src/js/panels/` с уникальным `id`.
2. Импортируйте ее в `src/App.jsx` и добавьте в нужный `View`.
3. Для перехода используйте действия из [`src/js/store/router/actions.js`](../src/js/store/router/actions.js): `setPage(view, panel)`, `goBack()`, `openModal(id)` и `closeModal()`. Например, существующий переход в справочник: `dispatch(setPage('home', 'directory'))`.
4. Для нового таба добавьте запись в `sections` в `AppLayout.jsx` и соответствующие `Root`/`View` в `App.jsx`. Для переключения табов используется `setStory(story, initial_panel)`.

Модальные окна регистрируются в `App.jsx` и получают `open` и `onClose`. Не меняйте историю браузера напрямую: действия роутера согласуют ее со стеком панелей и SwipeBack. После изменения навигации проверьте возврат со вложенного экрана, переключение табов, Back браузера и закрытие модального окна.

Панель [`placeholder_page`](../src/js/panels/placeholder_page.jsx) сохранена в `View` главной с текстом «Приложение недоступно в вашем регионе». На ней скрыта основная навигация. Для проверки в дебаг-меню есть пункт «Региональное ограничение»: он открывает тот же компонент в профиле с `id="debug_region"` и кнопкой возврата. Автоматического определения региона сейчас нет.

## Доступ и блокировки

Настройки находятся в [`src/config/access.js`](../src/config/access.js):

```js
export const accessConfig = {
    enabled: true,
    blockedUserIds: [],
};
```

Добавляйте VK ID в `blockedUserIds` числами без кавычек, например `[123456789, 987654321]`. Удаление ID снимает блокировку. Значение `enabled: false` закрывает приложение для всех с сообщением «Приложение временно недоступно». После изменения файла нужна новая сборка и публикация; уже открытое приложение нужно перезапустить. Сейчас список пуст, никто не заблокирован.

Если список непустой, перед открытием разделов проверяется `vk_user_id` из параметров запуска. При отсутствии ID запрашиваются параметры через `VKWebAppGetLaunchParams`. До завершения проверки разделы и фоновые загрузки прогресса не запускаются. Если пользователь не определен или настройки некорректны, показывается ошибка с повтором проверки. В обычном браузере без параметров VK при непустом списке доступ также не откроется.

Пункт «Блокировка пользователя» в дебаг-меню открывает предпросмотр `debug_blocked` с кнопкой возврата. У заблокированного пользователя кнопки возврата и основной навигации нет. Сброс данных аккаунта не меняет список блокировок в файле.

Это ограничение интерфейса в клиентском коде. Для защиты данных и запросов от обхода нужен сервер, который проверяет подпись параметров запуска VK и применяет блокировку на каждом защищенном запросе. Ключи и секреты в этот файл добавлять нельзя.

## VKUI и повторное использование

В `App.jsx` соблюдается порядок `ConfigProvider → AdaptivityProvider → AppRoot`; Redux `Provider` расположен выше в `index.jsx`. Тема, отступы безопасной области и режим адаптивности приходят из состояния приложения и параметров VK. При переносе экранов сохраняйте этот контекст, подключение CSS VKUI и используемые стили приложения. API компонентов сверяйте с установленной версией в `package.json` и [документацией VKUI](https://vkui.io/).

Это приложение, а не готовая библиотека компонентов. Для другого проекта можно отдельно переносить каталоги и компоненты, но нужно проверить их импорты и стили. Например, `NoticeBanner` использует VKUI и стили приложения, а `AppSnackbar` дополнительно вызывает виброотклик через Bridge. Панели обычно связаны с Redux и роутером.

Для запросов Bridge используйте [`src/js/services/bridge.js`](../src/js/services/bridge.js), где проверяются окружение, поддержка метода и время ожидания. Управление закрытием приложения и SwipeBack отдельно находится в `services/VK.js`. Сетевые операции и обработку ответов размещайте в сервисах, сохранение состояния в store, отображение в компонентах. При переносе в другой проект замените данные колледжа, ID пользователей, сообщества и ссылки, в том числе в `components/data/`, `services/community.js` и `services/donut.js`. ID приложения для Bridge берется из параметров запуска; настройки публикации находятся в [`vk-hosting-config.json`](../vk-hosting-config.json).

## Совместимость сохраненных данных

Ключи VK Storage и ID достижений и мемов уже используются в сохраненном прогрессе. Не переименовывайте их ради очистки кода и не привязывайте ID мема к имени файла. Если формат данных меняется, предусмотрите чтение старого формата или явную миграцию. В другом приложении VK используйте собственные ключи и каталоги.

Полный сброс координируется в [`src/js/store/account.js`](../src/js/store/account.js) через `resetAccountData()`. Новое сохраняемое состояние должно участвовать в этом сбросе и учитывать уже запущенные чтения и записи, чтобы они не восстановили удаленные данные. Для нового модуля добавьте reducer в [`src/js/store/reducers.js`](../src/js/store/reducers.js).

После изменений проверяйте мобильную и ПК-версию, светлую и темную темы, состояния загрузки и ошибки. Для сохраняемых данных отдельно проверьте повторный запуск и сброс аккаунта. Нативные разрешения, оплату и действия VK проверяйте в целевых клиентах VK.
